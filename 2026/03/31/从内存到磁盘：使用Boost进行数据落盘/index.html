概述

解决数据持久化问题，实际上就是解决数据的序列化和反序列化问题

serialize()什么时候被调用 ？

在序列化时

  1. 触发：执行 << 操作符。

  2. 查找：Boost 检查 p 的类型，寻找匹配的 serialize 函数。

  3. 调用：Boost 内部调用 serialize(oa, my_person, version)。

  4. 执行：进入你写的 serialize 函数体，将成员变量逐个“推”入输出流。

在反序列化时

  1. 触发：执行 >> 操作符。
  2. 查找：Boost 从输入流读取类名标记，寻找匹配的 serialize 函数。
  3. 调用：Boost 内部调用 serialize(ia, my_person, version)。
  4. 执行：进入函数体，从流中读取数据并“拉”回给成员变量。

非侵入式写法(Non-intrusive Serialization)：

通俗地说，就是：如果你没法改动一个类的源代码，你依然有办法让它支持序列化。

通常情况下，Boost 要求你在类内部写一个 serialize() 函数（嵌入式）。 但如果你面对的是以下情况，你就没法在类里面写代码了：

  • 标准库类：比如你不能去改 std::vector 的源码。
  • 第三方库：你下载了一个编译好的图形库，它的 Point 类没写序列化，你也改不了。
  • 遗留代码：公司的老代码，老板不准你动原有的类定义。

当类里面不方便写 serialize 时，Boost 允许你在类外面定义一个全局的 serialize 函数。

Binary Archive（二进制归档)

虽然 text_archive（文本归档）具有良好的可读性，方便调试，但在处理大规模生产数据时，它的缺点也显而易见：体积大、解析慢、存在精度损失。而 Binary Archive有很多优点:

  • 极速 I/O：二进制格式直接按字节拷贝内存数据，省去了将数字转换为 ASCII 字符的计算开销。
  • 空间精简：直接对数据进行二进制拷贝
  • 数据精准：完美保留浮点数的每一位精度，不存在舍入误差。
